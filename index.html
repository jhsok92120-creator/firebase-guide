Firebase 프로젝트 설정

홈페이지가 올라갈 원장님 전용 프로젝트(계정 공간)를 만들고 개발자에게 작업 권한을 주는 6가지 단계입니다.

⏱ 예상 소요시간 약 20분
📋 총 6단계
귀 병원 홈페이지는 원장님 명의의 Firebase 프로젝트 위에서 제작됩니다. 이렇게 하면 홈페이지 데이터와 계정 소유권이 온전히 원장님께 있으며, 저(개발자)는 편집 권한만 받아 제작·관리를 도와드리는 구조입니다.

STEP 1

Firebase 프로젝트 생성

홈페이지가 올라갈 원장님 전용 프로젝트를 만드는 단계입니다.
1
Firebase 콘솔 접속
구글 계정(가급적 병원용으로 계속 사용하실 계정)으로 로그인한 상태에서 아래 주소에 접속합니다.
https://console.firebase.google.com
2
새 프로젝트 만들기
'시작하기' 화면 아래쪽의 "새 Firebase 프로젝트 만들기" 카드를 클릭합니다.
3
프로젝트 이름 입력
병원 이름이 들어가도록 입력합니다. (예: myclinic-website) 입력하면 아래에 myclinic-a1b2c와 같은 형태로 프로젝트 ID가 자동 생성됩니다.
💡 이 프로젝트 ID는 이후 웹사이트 주소의 일부가 될 수 있으니, 화면에 표시된 ID를 캡처해 두시거나 저에게 전달해 주시면 좋습니다.
4
Google 애널리틱스 설정
"이 프로젝트에 Google 애널리틱스 사용 설정" 항목은 꺼주셔도 무방합니다 (선택 사항이며 나중에 추가 가능).
5
프로젝트 생성 완료
"프로젝트 만들기" 버튼을 누르고 잠시 기다리면 완료됩니다. "계속" 버튼을 눌러 프로젝트 대시보드로 이동합니다.
STEP 2

요금제를 Blaze로 업그레이드

이미지 저장, 실시간 데이터베이스 등 정상 작동을 위해 필요한 단계입니다.
⚠️ "Blaze"는 사용량 기반 종량제 요금제입니다. 병원 홈페이지 수준의 트래픽에서는 대부분 월 0원 ~ 소액 수준이며, 무료 사용량 한도 내에서는 과금되지 않습니다.
⚠️ 요금제 변경은 프로젝트 소유자(Owner)만 할 수 있습니다. 제가 편집자(Editor) 권한으로 대신 해드릴 수 없는 단계이니, 이 STEP은 꼭 원장님이 직접 진행해 주세요.
1
요금제 변경 메뉴 이동
프로젝트 대시보드 왼쪽 하단의 "업그레이드"(Upgrade) 버튼, 또는 ⚙️ 설정 → 사용량 및 결제(Usage and billing)로 이동합니다.
2
Blaze 요금제 선택
"Blaze - 사용한 만큼만 지불" 옵션을 선택하고 "플랜 선택"을 클릭합니다.
3
결제 계정 연결
기존 Google 결제 계정이 있다면 선택하고, 없다면 새로 만들어 카드 정보를 등록합니다.
⚠️ 결제 계정을 새로 만들 때 "계정 유형"은 반드시 "개인"으로 선택해 주세요. "사업자/조직"을 고르면 사업자등록번호와 세금 정보 입력이 필요해 개원 전에는 진행이 막히고, 이미 개원하셨더라도 불필요하게 복잡해집니다. 개인으로 해도 홈페이지 운영에는 아무 차이가 없습니다.
4
예산 알림 설정 (선택, 권장)
"예산 알림" 금액을 예를 들어 10,000원으로 설정해두면, 초과 시 이메일로 알려줍니다.
STEP 3

Firestore Database 설정

예약 문의, 공지사항 등 데이터를 저장하는 공간을 만드는 단계입니다.
1
Firestore 메뉴 이동
왼쪽 메뉴에서 데이터베이스 및 스토리지를 클릭해 펼친 뒤, "NoSQL" 항목 중 Firestore를 선택합니다.
💡 같은 목록에 "Realtime Database"도 보이는데, 이건 다른 상품이니 헷갈리지 말고 꼭 Firestore를 선택해 주세요.
2
데이터베이스 만들기
"데이터베이스 만들기(Create database)" 버튼을 클릭합니다. "에디션"을 고르는 항목이 보이면 Standard를 선택하고, "데이터베이스 ID"는 기본값 (default) 그대로 둡니다.
3
위치(리전) 선택
반드시 아래 리전으로 선택해 주세요.
위치: asia-northeast3 (Seoul)
💡 서울 리전을 선택해야 국내 접속 속도가 가장 빠릅니다. 한 번 선택하면 이후 변경이 불가능합니다.
4
보안 규칙 모드 선택
"프로덕션 모드에서 시작(Start in production mode)"을 선택하고 "만들기"를 클릭합니다. 처음부터 외부 접근이 차단된 상태로 시작되며, 이후 제가 필요한 접근 규칙만 안전하게 설정해 드립니다.
STEP 4

Storage 설정

홈페이지에 들어갈 사진, 이미지 파일을 저장하는 공간을 만드는 단계입니다.
1
Storage 메뉴 이동
왼쪽 메뉴에서 데이터베이스 및 스토리지를 클릭해 펼친 뒤, "객체 스토리지" 항목의 Storage를 선택합니다.
2
시작하기
"시작하기(Get started)" 버튼을 클릭합니다.
3
위치(리전) 선택
Firestore와 동일하게 아래 리전을 선택하고 "다음"을 클릭합니다.
위치: asia-northeast3 (Seoul)
4
보안 규칙 선택
"프로덕션 모드에서 시작"을 선택하고 "다음"을 클릭합니다.
5
완료
"완료(Done)"를 클릭하면 Storage 설정이 끝납니다.
STEP 5

개발자를 편집자(Editor)로 추가

제가 홈페이지 제작·관리 작업을 할 수 있도록 프로젝트에 초대해 주시는 마지막 단계입니다.
1
사용자 및 권한 메뉴 이동
왼쪽 메뉴 ⚙️ 설정 → 사용자 및 권한(Users and permissions)을 클릭합니다.
2
구성원 추가
"구성원 추가(Add member)" 버튼을 클릭한 뒤, 아래 이메일을 입력합니다.
jhsok92120@gmail.com
3
역할(권한) 지정
역할 선택에서 편집자(Editor)를 선택한 뒤 "구성원 추가"를 클릭하여 완료합니다.
💡 소유자(Owner) 권한은 원장님만 유지하시고, 개발자에게는 편집자(Editor) 권한만 부여하시면 됩니다.
STEP 6

추가 권한 부여 (공지사항 등 기능 관리용)

편집자(Editor) 권한만으로는 공지사항처럼 자동화 기능(Cloud Functions)이 들어간 부분을 관리할 때 오류가 날 수 있어, 아래 3가지 권한을 추가로 부여해 주셔야 합니다.
⚠️ 이 3가지 권한은 Firebase 콘솔의 "사용자 및 권한" 화면에서는 추가할 수 없고, Google Cloud 콘솔이라는 별도 화면에서 추가해야 합니다. 아래 순서대로 진행해 주세요.
1
Google Cloud 콘솔 IAM 페이지 접속
주소창에 아래 주소를 입력하여 접속한 뒤, 현재 사용 중이신 프로젝트가 맞는지 상단에서 확인합니다.
console.cloud.google.com/iam-admin/iam
2
주 구성원(jhsok92120@gmail.com) 찾기
목록에서 jhsok92120@gmail.com 계정을 찾아, 오른쪽의 연필(✏️) 모양 "주 구성원 수정" 아이콘을 클릭합니다.
3
역할 3개 추가
"다른 역할 추가(Add another role)"를 3번 클릭하여, 아래 3개 역할을 각각 검색해서 추가합니다.
서비스 계정 사용자 (Service Account User)
Cloud Run 관리자 (Cloud Run Admin)
Cloud 함수 관리자 (Cloud Functions Admin)
4
저장
하단의 "저장(Save)" 버튼을 클릭하면 반영됩니다. 기존에 가지고 있던 편집자(Editor) 역할은 그대로 유지되며, 이번 3개 역할이 추가로 더해지는 것입니다.

도메인 연결

구매하신 도메인을 홈페이지 주소로 실제 연결하는 5가지 단계입니다.

⏱ 예상 소요시간 10분 + 대기 최대 24시간
📋 총 5단계
도메인은 원장님 명의로 직접 구매하셔야 합니다 (결제가 걸린 부분이라 대신 진행이 어렵습니다). 구매 이후 Firebase와 연결하는 작업은 제가 안내해 드리며, 등록업체 로그인 정보를 공유해 주시면 이 단계도 제가 대신 처리해 드릴 수 있습니다.

STEP 1

도메인 구매 확인

가비아, 후이즈 등 국내 등록업체에서 원장님 명의로 도메인을 구매합니다.
1
도메인 구매
가비아(gabia.com) 등에서 원하는 도메인 주소를 검색하고 구매를 완료합니다.
2
로그인 정보 확보
등록업체 아이디/비밀번호를 기억해 두세요. DNS 설정 작업 시 필요합니다.
STEP 2

Firebase Hosting에 도메인 추가

Firebase 콘솔에서 연결할 도메인을 등록하는 단계입니다.
1
Hosting 메뉴 이동
Firebase 콘솔 → 왼쪽 메뉴 호스팅 및 서버리스를 클릭해 펼친 뒤 Hosting을 선택합니다.
2
커스텀 도메인 추가
"커스텀 도메인 추가(Add custom domain)" 버튼을 클릭하고, 구매한 도메인 주소를 입력한 뒤 "계속"을 클릭합니다.
3
설정 방식 선택
"빠른 설정"과 "고급 설정" 중 하나를 고르는 화면이 나옵니다. 새로 산 도메인이거나 아직 다른 홈페이지에 쓰고 있지 않다면 "빠른 설정"을 선택합니다.
💡 기존 홈페이지에 이미 쓰고 있는 도메인을 옮기는 경우(이전 홈페이지가 열려 있는 상태)라면 "고급 설정"이 맞습니다. 어느 쪽인지 애매하면 저에게 물어봐 주세요.
STEP 3

소유권 확인 (TXT 레코드)

이 도메인이 정말 원장님 소유인지 확인하는 절차입니다.
1
TXT 레코드 값 복사
Firebase가 화면에 보여주는 TXT 레코드 값을 복사합니다.
2
등록업체 DNS 설정 이동
가비아 등 등록업체 사이트 로그인 → 도메인 관리 → DNS 설정(네임서버 관리)으로 이동합니다.
3
TXT 레코드 추가
복사한 값을 TXT 레코드로 추가하고 저장한 뒤, Firebase 화면에서 "확인"을 클릭합니다.
💡 반영까지 몇 분에서 최대 24시간이 걸릴 수 있습니다. 바로 확인되지 않아도 정상이니 시간을 두고 다시 눌러 주세요.
⚠️ 이 TXT 레코드는 확인이 끝난 뒤에도 삭제하지 말고 그대로 두세요. Firebase가 보안 인증서를 자동 갱신할 때 계속 사용합니다.
STEP 4

연결 레코드 등록 (A 레코드)

실제로 도메인이 홈페이지로 연결되도록 만드는 핵심 단계입니다.
1
A 레코드 값 복사
Firebase가 화면에 알려주는 IP 주소(A 레코드)를 복사합니다. 화면에 표시된 값을 그대로 쓰시면 됩니다.
2
등록업체 DNS에 A 레코드 추가
같은 DNS 설정 화면에서 A 레코드로 등록합니다. 이전 홈페이지 업체가 남겨둔 기존 A 레코드가 있다면 Firebase 화면의 안내대로 삭제합니다.
3
URL 자동연결(포워딩) 기능 끄기
가비아 등에서 "URL 자동연결" 또는 "포워딩" 기능이 켜져 있으면 반드시 꺼주세요.
⚠️ 이 기능이 켜져 있으면 A 레코드와 충돌해서 사이트가 열리지 않을 수 있습니다.
STEP 5

SSL 인증서 발급 대기

보안 연결(https)을 위한 인증서가 자동으로 발급되는 단계입니다.
1
자동 발급 대기
별도로 하실 작업은 없습니다. Firebase가 자동으로 SSL 인증서를 발급합니다.
2
발급 완료 확인
보통 몇 시간에서 최대 24시간 정도 소요됩니다. 이 기간 동안 사이트가 일시적으로 안 열릴 수 있으나 정상적인 과정입니다.
💡 Firebase Hosting 화면의 상태는 "설정 필요" → "대기 중" → "연결됨" 순서로 바뀝니다. "연결됨"이 뜨면 끝입니다. 24시간이 지나도 "설정 필요"에 머물러 있으면 저에게 알려 주세요.

STEP 1

Kakao Developers 가입 · 로그인

카카오맵 API를 사용하려면 개발자 사이트 가입이 필요합니다.
1
사이트 접속
아래 주소로 접속합니다.
https://developers.kakao.com
2
카카오 계정으로 로그인
병원용으로 계속 사용하실 카카오 계정으로 로그인(또는 신규 가입)합니다.
STEP 2

애플리케이션 생성

카카오맵을 사용할 앱(프로젝트)을 하나 만듭니다.
1
내 애플리케이션 이동
상단 메뉴에서 "내 애플리케이션"을 클릭합니다.
2
애플리케이션 추가
"애플리케이션 추가하기" 버튼을 클릭한 뒤 필수 항목 3개를 입력하고 "저장"을 클릭합니다.
앱 이름: 병원 이름  ·  회사명: 병원 이름  ·  카테고리: 병원과 가장 가까운 항목
💡 카테고리는 어떤 것을 골라도 지도 기능에는 영향이 없습니다. 앱 아이콘 등 나머지 항목은 비워두셔도 됩니다.
STEP 3

카카오맵 사용 설정

심사 없이 스위치만 켜면 됩니다.
1
카카오맵 메뉴 이동
생성한 앱을 클릭해 앱 관리 화면으로 들어간 뒤, 왼쪽 메뉴에서 [카카오맵] → [사용 설정]으로 이동합니다.
2
상태 ON
"상태" 스위치를 ON으로 바꿉니다.
💡 켜고 나면 앱 정보에 "카카오맵 무료 쿼터" 표시가 붙습니다. 이 표시가 있으면 병원 홈페이지 수준에서는 무료로 사용됩니다. (한 카카오 계정에서 카카오맵을 처음 켜는 앱에만 무료 쿼터가 주어지니, 이 계정에 다른 앱을 만들어 두신 적이 있다면 저에게 알려 주세요.)
STEP 4

JavaScript 키 확인

홈페이지 코드에 넣을 키를 확인하고 저에게 전달해 주시는 단계입니다.
1
플랫폼 키 메뉴 이동
앱 관리 화면 왼쪽 메뉴에서 [플랫폼 키] → [JavaScript 키]를 클릭합니다. (예전 안내에 있던 "앱 설정 → 앱 키" 메뉴는 없어졌습니다)
2
JavaScript 키 복사
화면 상단에 표시되는 JavaScript 키 값을 복사해서 저에게 전달해 주세요. (REST API 키나 어드민 키는 지도에 쓰지 않으니 보내지 않으셔도 됩니다)
STEP 5

JavaScript SDK 도메인 등록

등록된 도메인에서만 지도가 정상적으로 표시됩니다. 이 단계를 빠뜨리면 지도가 안 뜹니다.
1
JavaScript SDK 도메인 항목 찾기
STEP 4와 같은 [플랫폼 키] → [JavaScript 키] 화면을 아래로 내리면 "JavaScript SDK 도메인" 항목이 있습니다. "도메인 등록" 버튼을 클릭합니다.
2
홈페이지 주소 입력
실제 홈페이지 도메인 주소를 입력하고 저장합니다. (예: https://myclinic.co.kr)
💡 제가 알려드린 Firebase 기본 주소(예: https://myclinic-a1b2c.web.app)도 "도메인 등록"을 한 번 더 눌러 추가해 두시면, 도메인 연결(2번 탭) 전에도 지도 확인이 가능합니다. 실제 도메인 주소를 아직 모르시면 일단 이 기본 주소만 등록하셔도 됩니다.

네이버 지도 API 설정

네이버 지도로도 "오시는 길"을 보여주고 싶을 때 필요한 5가지 단계입니다. 카카오맵과 별개로 등록해야 합니다.

⏱ 예상 소요시간 약 10분
📋 총 5단계
네이버 지도 API는 네이버 클라우드 플랫폼(NCP)을 통해 발급받습니다. 결제 수단(카드) 등록이 필요하지만, 일반적인 병원 홈페이지 트래픽 수준에서는 월 무료 제공량(약 1,000만 건) 안에서 대부분 해결되어 비용이 거의 발생하지 않습니다.

STEP 1

네이버 클라우드 플랫폼 가입 · 로그인

네이버 지도 API는 네이버 클라우드 플랫폼(NCP) 계정으로 발급받습니다.
1
사이트 접속
아래 주소로 접속합니다.
https://www.ncloud.com
2
가입 또는 로그인
네이버 아이디로 가입/로그인하거나, 별도 NCP 계정을 만듭니다. (병원용으로 계속 사용하실 계정 권장)
STEP 2

결제 수단 등록

Application 등록을 위해 카드 등록이 필요합니다.
💡 지도 표시(Dynamic Map)는 월 1,000만 건까지 무료라서 병원 홈페이지 수준에서는 실제 과금이 거의 없습니다. 카드 등록 과정에서 결제되는 금액은 없습니다.
1
결제 수단 등록
가입 완료 화면의 "결제 수단 등록" 버튼(또는 화면 오른쪽 위 "결제수단등록")을 클릭하고, 신용/체크카드를 선택해 휴대폰 인증 후 카드 번호와 유효기간을 입력합니다.
STEP 3

Application 등록

지도를 사용할 애플리케이션을 등록하는 단계입니다.
1
Maps 메뉴 이동
콘솔 왼쪽 Menu → All Services → Application Services → Maps로 이동합니다.
2
이용 신청 (처음 한 번)
"+ 이용 신청" 버튼이 보이면 클릭하고 약관에 동의합니다. 이미 신청된 상태면 이 버튼이 없으니 다음으로 넘어갑니다.
3
Application 등록
"+ Application 등록" 버튼을 클릭하고 Application 이름을 영문으로 입력합니다. (예: myclinic-map)
⚠️ 이름은 영문자·숫자·하이픈(-)만 가능하고 영문자로 시작해야 합니다. 한글 병원 이름을 넣으면 등록되지 않습니다.
4
API 선택
API 선택 항목에서 Dynamic Map에 체크합니다. 다른 항목은 체크하지 않아도 됩니다.
⚠️ Dynamic Map이 체크되어 있지 않으면 홈페이지에서 지도가 뜨지 않고 오류(429)가 납니다. 등록 전에 체크 여부를 한 번 더 확인해 주세요.
STEP 4

서비스 환경(Web 서비스 URL) 등록

같은 등록 화면 아래쪽에서, 지도를 표시할 홈페이지 주소를 등록하는 단계입니다. 등록한 주소에서만 지도가 뜹니다.
1
Web 서비스 URL 입력
"서비스 환경 등록" 항목의 Web 서비스 URL 칸에 홈페이지 주소를 아래 형식으로 입력하고 "+ 추가"를 클릭합니다.
http://myclinic.co.kr
💡 이 칸은 http://로 시작하는 형식으로 넣으면 됩니다(https 홈페이지여도 http로 입력, www는 빼고). 여기서만 특별히 이렇게 입력하는 것이니 다른 서비스의 주소 입력과 헷갈리지 마세요.
2
Firebase 기본 주소도 추가
도메인 연결 전에도 지도를 확인할 수 있도록, 제가 알려드린 Firebase 기본 주소(예: http://myclinic-a1b2c.web.app)도 한 줄 더 추가합니다. 그 뒤 화면 아래 "등록"을 클릭하면 끝입니다.
⚠️ 도메인 연결(2번 탭)이 아직이라 실제 주소를 모르시면, 일단 Firebase 기본 주소만 넣어 등록하고 나중에 저에게 알려주시면 제가 추가 요청을 드립니다.
STEP 5

인증 정보(Client ID) 확인

홈페이지 코드에 넣을 키를 확인하고 저에게 전달해 주시는 단계입니다.
1
인증 정보 보기
등록한 Application 목록에서 방금 만든 앱 이름 아래 "인증 정보" 버튼을 클릭합니다.
2
Client ID 복사
"인증 정보" 창에는 아래처럼 두 줄이 나옵니다. 이 중 위쪽 짧은 값(Client ID)만 복사해서 저에게 전달해 주세요.
Client ID       k7x2abq9mz  ← 이것 (영문·숫자 10자 내외)
Client Secret Qw3rTy9uIoP1aSdFgHjKl2ZxCvBnM4qWeRtYuIoP  ← 이건 보내지 마세요 (길고 복잡한 값)
⚠️ 위 값은 모양을 보여드리기 위한 예시이며, 실제 값은 원장님 화면에 표시된 것을 쓰셔야 합니다. 자주 생기는 실수: Client Secret을 보내거나, Application 이름을 보내거나, NCP 계정의 API 인증키(Access Key)를 보내는 경우입니다. "Client ID" 글자 바로 옆의 짧은 값이 맞습니다. 헷갈리시면 인증 정보 창 전체를 캡처해서 보내주셔도 됩니다.

홈페이지 방문자 수와 유입 경로를 확인할 수 있도록 통계 도구를 연결하는 5가지 단계입니다.

방문자가 홈페이지에 들어와서 어떤 페이지를 봤는지, 어디서 유입됐는지 알려주는 통계 도구예요.

Google 애널리틱스는 무료이며, 원장님이 직접 가입하고 계정 소유권을 가지시는 것을 권장드립니다. 측정 ID만 저에게 전달해 주시면 홈페이지 연결은 제가 진행합니다.

STEP 1

Google 애널리틱스 접속 · 계정 만들기

방문자 통계를 볼 수 있는 계정을 새로 만드는 단계입니다.
1
사이트 접속
구글 계정으로 로그인한 상태에서 아래 주소에 접속합니다.
https://analytics.google.com
2
측정 시작
"측정 시작" 버튼을 클릭하고, 계정 이름에 병원 이름을 입력합니다. 아래 "데이터 공유 설정" 체크박스들은 기본값 그대로 두고 "다음"을 클릭합니다.
STEP 2

속성(웹사이트) 만들기

이 홈페이지를 나타내는 속성을 생성합니다.
1
속성 이름 입력
속성 이름에 홈페이지 이름(예: 병원명 홈페이지)을 입력합니다.
2
시간대 · 통화 선택
보고 시간대는 "대한민국", 통화는 "대한민국 원(₩)"을 선택합니다.
STEP 3

비즈니스 정보 입력

병원 업종에 맞는 기본 정보를 선택하는 단계입니다.
1
업종 · 규모 선택
업종 카테고리(의료/건강 등), 비즈니스 규모를 선택합니다.
2
비즈니스 목표 선택
"비즈니스 목표" 화면이 나오면 아무거나 하나 이상 체크하고 "만들기"를 클릭합니다. (예: "방문자 행동 파악" 또는 "기준 보고서 보기") 어떤 걸 골라도 수집되는 데이터는 같고, 기본 보고서 구성만 달라집니다.
3
약관 동의 및 계정 생성
Google 애널리틱스 서비스 약관에 동의하면 계정과 속성이 만들어집니다.
STEP 4

웹 데이터 스트림 추가

실제 홈페이지 주소를 연결하는 핵심 단계입니다.
1
플랫폼 선택
데이터 수집 플랫폼에서 "웹"을 선택합니다.
2
웹사이트 URL 입력
실제 홈페이지 도메인 주소를 입력하고, 스트림 이름을 입력한 뒤 "스트림 만들기"를 클릭합니다.
💡 도메인 연결(2번 탭)이 아직이라면, 일단 Firebase 기본 주소(예: myclinic-a1b2c.web.app)로 먼저 만들어도 괜찮습니다. 나중에 도메인이 연결되면 자동으로 함께 추적됩니다.
STEP 5

측정 ID 확인

홈페이지 코드에 넣을 키를 확인하고 저에게 전달해 주시는 마지막 단계입니다.
1
스트림 세부정보 확인
생성된 웹 데이터 스트림을 클릭하면 상단에 "측정 ID"가 표시됩니다. (예: G-XXXXXXXXXX)
2
측정 ID 전달
이 측정 ID를 복사해서 저에게 전달해 주세요.

구글 서치콘솔 접속

구글 계정으로 로그인한 상태에서 시작하는 단계입니다.

3

화면 맨 위 검색창에 홈페이지 주소를 붙여넣고 Enter를 누릅니다. "URL이 Google에 등록되어 있습니다"라고 나오면 색인 완료, 아니면 "색인 생성 요청" 버튼을 눌러 요청할 수 있습니다.
💡 "URL이 Google에 등록되어 있지 않습니다"가 뜨더라도 등록 초기엔 흔한 일이에요. 색인 생성 요청을 누르고 며칠 기다리시면 됩니다. 2주가 지나도 그대로면 저에게 알려 주세요.

발급ID · 스크립트 확인 및 전달

홈페이지에 넣을 코드를 확인하고 저에게 전달해 주시는 단계입니다.
1
발급ID 확인
등록이 끝나면 열리는 "사이트정보" 화면에 발급ID가 표시됩니다. (영문·숫자가 섞인 짧은 코드)
2
스크립트 복사 및 전달
같은 화면 오른쪽 아래의 "스크립트복사" 버튼을 눌러 복사한 내용을 저에게 보내 주세요. 복사가 어려우시면 발급ID만 캡처해서 보내주셔도 됩니다.
💡 구글 애널리틱스의 측정 ID(G-XXXX)와는 다른 코드예요. 헷갈리지 않게 "네이버용"이라고 표시해서 보내주시면 좋습니다.
STEP 4

스크립트 설치

전달해 주신 코드를 홈페이지에 삽입하는 단계입니다.
1
스크립트 삽입
전달받은 스크립트를 홈페이지 모든 페이지의 </body> 바로 위에 삽입합니다.
💡 이 단계는 제가 대신 진행합니다. 발급ID 또는 스크립트만 전달해 주시면 됩니다.
STEP 5

수집 확인

통계가 정상적으로 쌓이는지 확인하는 단계입니다.
1
설치 완료 안내 대기
삽입이 끝나면 제가 정상 수집 여부까지 확인한 뒤 안내드립니다.
2
대시보드 확인
설치 다음 날부터 네이버 애널리틱스 첫 화면(대시보드)에서 방문자 수와 유입 경로를 보실 수 있습니다. 설치 당일에는 숫자가 0으로 보여도 정상입니다.
💡 구글 애널리틱스와 숫자가 조금 다르게 나오는 건 집계 기준이 달라서 그런 것이니 걱정하지 않으셔도 됩니다.
